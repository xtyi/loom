# 决策 0004 执行 DAG 与 schedule 分离

- 状态：已接受，替代原“按 node id 显式提交”决策
- 更新：2026-10-23

## 背景

runtime 接收的图是已经绑定 KernelUnit 实现的调用图，不是等待融合、精度选择或代码生成的模型语义图。原决策将确定性与按 id 提交绑定，并认为依赖调度必须理解算子语义；这两个前提都不成立。

## 决定

1. 执行 DAG 声明数据依赖与额外 `after` 边；schedule 单独描述合法的提交顺序和 stream 分配。
2. 缺省使用确定性的 Kahn 拓扑排序，每次选择就绪节点中 id 最小者，全部使用 stream 0。节点 id 不代表执行次序。
3. 外部 schedule 必须覆盖全部节点恰好一次，并满足所有依赖。无效时拒绝，不能静默改变调用者的方案。
4. 首批原型只接受不可变 slot、单生产者与只读外部输入，不支持 alias、原地更新、persistent 状态、多流或控制流。
5. 扩展多流后，内存复用以 happens-before 完成关系为依据；主机提交顺序不足以证明安全。扩展原地更新前先定义逻辑值版本与底层存储冲突规则。

引擎可以做结构校验、拓扑排序、依赖同步和受约束的调度，不做融合、布局重排或自动精度策略。高级调度暂缓是实施范围选择，不是语义边界的必然禁令。

## 保证与限制

完整的读写、别名和副作用声明是正确调度的前提。图校验器不能保证未声明的二进制访问无竞争。稳定提交顺序也不保证并发完成顺序或 kernel 内数值运算逐位确定。

## 验证

覆盖生产者 id 大于消费者、分支汇合、重复/悬空引用、缺失或多个生产者、数据/after 环，以及显式 schedule 的遗漏、重复和逆依赖。重排输入节点数组不能改变默认 schedule。
