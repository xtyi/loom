# 决策 0002 KernelUnit 是契约原子，一个实现一个 `.so`

- 状态：已接受
- 时间：2026-10

## 背景

需要确定引擎与外部 kernel 的边界粒度。三个候选：

- 一个算子一个函数指针，最细。
- 一个融合组一个 `.so`，本方案。
- 一个模型一个 `.so`，最粗。

## 决定

采用第二种：KernelUnit 指一个融合后的计算块，对应一个 `.so` 和一个 `lm_ku_entry_v1` 入口。

每个实现（ref、fast、tuned、不同 arch 变体）单独一个 `.so`，而不是在一个 `.so` 内含多个实现。

## 理由

| 维度 | 一个实现一个 `.so` | 一个 KernelUnit 一个 `.so` |
|---|---|---|
| 编译失败的影响面 | 只影响一个变体 | 影响全部变体 |
| arch 分离（sm_86 与 sm_90a） | 天然独立 | 需要在包内分发 |
| 按需加载 | 可以只加载用到的 | 必须全部加载 |
| 包体积 | 略大 | 略小 |
| dlopen 次数 | 多，约 60 到 180 次 | 少 |

决定性理由是 sm_90a 与 sm_86 必须使用不同的编译选项。混在一个 `.so` 里会让按需加载和失败隔离同时失效。

`dlopen` 成本约 0.1 到 1 ms，可以在加载期一次性付清，不影响推理的关键路径。

## 后果

正面效果是失败隔离、arch 独立、可以单独替换、单独审计与签名。

负面效果是包体积增大。YOLO 约 60 个 `.so`，每个 100 到 500 KB，总计约 20 MB。加载期需要批量 `dlopen`，已用惰性加载和预热接口缓解。
